1. INTRODUCTION                                        *conjurer-introduction*

Conjurer adds a **conjure** |operator| that transforms text with a
natural-language intent. Target text with any motion or text object,
describe the change, and the replacement is spliced in asynchronously:
>
    ~ip         target the inner paragraph
    Conjure: convert to a pure function<CR>
<
The motion comes first, then the intent prompt — so `~ip` feels exactly like
`dip` or `g~ip`: pick the target, then cast.

While the request is in flight the region is locked and the model's own
narration streams into it as virtual lines — see |conjurer-narration|. The
editor is never blocked.

Why the `~` key? Vim itself considers `~` an operator: the built-in
'tildeop' option exists solely to turn `~` into `~{motion}`. Its stock
behavior (toggle case) is fully covered by |g~|, |gu| and |gU|, so nothing
is lost — conjurer upgrades the transformation the key already carries,
from "flip case" to "apply intent".

==============================================================================
2. USAGE                                                      *conjurer-usage*

Call the setup function once (all arguments optional, see
|conjurer-configuration|):
>lua
    require("conjurer").setup()
<
Then, over any motion:

    `~ip`    conjure over the inner paragraph
    `~i{`    conjure inside braces
    `~3j`    conjure this line and the next three
    `2~j`    same — counts multiply into the motion, like |d| or |c|
    `~~`     conjure the current line (doubling, like |dd| / |yy|)
    `3~~`    conjure three lines
    `v~`     conjure the visual selection
    `~Vip`   forced linewise, see |o_V|

After the motion, the prompt appears. Type the intent and press <CR>; abort
with <Esc>. The prompt is |input()|-backed, so <Up> recalls previous
intents.

Undo: each conjure is a single undo step — |u| un-conjures.

==============================================================================
3. MAPPINGS                                                *conjurer-mappings*

Default mappings (all configurable, see |conjurer-configuration|):

                                                                 *conjurer-~*
~{motion}               Conjure over {motion}. Prompts for an intent after
                        the motion. With a register prefix, see
                        |conjurer-registers|. Blockwise motions are not
                        supported.

                                                                *conjurer-~~*
~~                      Conjure over [count] lines, like |dd|.

                                                               *conjurer-v_~*
{Visual}~               Conjure over the selection (characterwise or
                        linewise).

The stock behavior of `~` remains available as |g~|, |gu|, |gU|, |v_u| and
|v_U| — e.g. `g~l` flips the case of the character under the cursor.

4. NARRATION AND LOCKING                                  *conjurer-narration*

While a conjure is in flight:

- The target region is highlighted with |hl-ConjurerPending| and **locked**:
  any edit that changes text inside it is immediately reverted (a warning
  points to |:ConjureCancel|). Everything outside the region stays fully
  editable.

- The model narrates what it is doing, and the narration streams into the
  region as virtual lines (|hl-ConjurerNarration|). The first line shows the
  intent, CLIPPED: virtual text is a single line, so a long or multi-line
  intent — a plugin driving |conjurer-api| may send a whole specification —
  would otherwise render its newlines as `^@` and run off the window. Only
  the display is trimmed; the model always receives the intent whole.

- The intent line says which PHASE the model is in — `thinking…` then
  `writing…` — read off the stream rather than guessed. A large request
  spends most of its life in a thinking block, and the CLI sends no thinking
  text for it: measured, a thinking block opens, a signature arrives at the
  end, and not one character in between. There is nothing to show, so what
  is shown is which block is open.

- The intent line carries ELAPSED time, because most of a long cast is
  silence. Measured against the CLI: a request produces nothing for its
  first few seconds, and a large one for minutes — the model thinks before
  it writes a word. With nothing moving that is indistinguishable from a
  hang, and the clock is the difference between waiting and wondering.

- The RESULT streams too, under the narration and in |hl-ConjurerPreview|.
  The two are different things — narration is the model talking about the
  work, the preview is the work — and a caller that asks for a page of text
  should be able to watch it arrive rather than wait for it. Only the tail
  is kept on screen: a preview that fills the window is the wait it
  replaced. Nothing touches the buffer until the splice, as before. >

    local function fetch_user(id)          ← dimmed, locked
     ✨ conjuring: add error handling
        · wrapping the decode in a pcall
        return data                        ← the result, as it streams
      local res = http.get("/users/" .. id)
      ...
<
- When the replacement lands, the narration disappears, the text is spliced
  in as a single undo step, and the new text flashes briefly.

Narration requires a provider that streams (the default CLI and API
providers both do). Set `narration = false` in |conjurer.setup()| to show
only the pending header. Nothing is written to the buffer until the final
splice — cancelling leaves the file byte-identical.

5. REVIEWING RESULTS                                          *conjurer-review*

With `review = true`, a finished conjure lands in the buffer immediately, but
instead of stopping there it opens a native two-way diff in a new tabpage: a
frozen snapshot of the whole file as it was on the left, and your real,
already-patched buffer on the right, both with 'diff' set. |]c|, |[c|, |do|
and |dp| all work exactly as they would in any other diff.

Crucially, the right-hand side is not a copy — it is the actual file. The
region is no longer locked once a draft exists (see |conjurer-narration|,
which only locks the *generating* phase, before there's anything to look
at): you're free to scroll anywhere in the buffer for context, or edit the
draft directly, while deciding:

    :ConjureAccept          stop reviewing and keep whatever the buffer
                             currently holds, close the diff
    :ConjureReject           undo the draft (and any further edits you made
                             to it) back to the exact pre-conjure text
    :ConjureRetry {feedback} revert the draft, then send it plus your
                             feedback back to the model, which revises
                             rather than starting over

Accept doesn't need to write anything — the change already happened the
moment review began. If you used `do`/`dp`, or just edited the text
directly, whatever's live is what stays. All three commands work from either
window of the diff tab.

Closing the diff yourself (`:tabclose`, `:q` on both panes, etc.) without
running one of the three commands is treated as a reject: the draft is
reverted and a warning notes the review was discarded — the region never
ends up silently keeping an undecided change.

`:ConjureCancel` run from inside a review reverts and closes it (equivalent
to reject); run from the source buffer while a review is open elsewhere on
the same file, it also reverts that review rather than leaving the draft in
place.

Off by default — set `review = true` in |conjurer.setup()| to turn it on.

6. AGGREGATE CONJURING                                    *conjurer-aggregate*

One intent, many sites. Populate the quickfix list with any of Vim's native
verbs — |:grep|, |:vimgrep|, LSP references, |:cexpr|, a hand-curated list —
prune it (|:Cfilter|, or just delete rows), then:
>
    :ConjureAll convert these to structured logging
<
Every valid entry becomes a site. A bare entry is expanded to the smallest
multi-line syntax node starting on its line — a grep hit on the first line
of a four-line call edits the whole call, not one line of it — while
entries carrying an explicit end_lnum are used verbatim and buffers without
a parser fall back to the line (`region_expand = false` turns expansion
off). Casts run with bounded concurrency (`max_concurrent`, default 4),
and sites in the same file run one at a time so one splice can never
disturb another's pending region. Each site tracks its own state:

    pending    queued, not started
    running    request in flight
    done       result applied
    skipped    the model returned the text unchanged (a false-positive
               entry, tolerated for free), or the site overlaps another
    failed     the request errored
    rejected   you reverted it

Re-running |:ConjureAll| is idempotent: settled sites are left alone, only
pending and failed ones cast — so "run, discover more sites, |:grepadd|,
run again" needs no special handling.

Reviewing happens in place, at your pace: walk the list with |:cnext| (entry
positions auto-adjust as buffers change, so you land on the applied text),
judge each site in its real surroundings, |:ConjureRejectSite| any you don't
want — it restores that site's original text exactly — or
|:ConjureRetrySite| with feedback to have the model revise its own draft.
`review = true` does not open diff tabs for aggregate casts; the list is the
review surface.

|:ConjureNext| casts just the current entry and advances, for a careful
one-at-a-time pass. The aggregate intent also becomes the operator's
remembered intent, so a site the search missed is one `~ip` + <CR> (or |.|)
away — see |conjurer-repeat|. |:ConjureRejectAll| unwinds the whole batch:
queued sites are dropped, in-flight requests are killed, applied sites
revert to their exact original text. (Plain |u| stays honest too — each
site is one undo step in its own buffer.)

                                                          *conjurer-exemplar*
N independent casts asked to "pick a convention" will pick two. The fix is
an exemplar: one finished, approved result that every site's request
carries with the instruction to match its style exactly. Conjurer infers it
from the natural pilot workflow — cast ONE site first (|:ConjureNext|),
judge it, fix it by hand or with |:ConjureRetrySite| until it's right, then
|:ConjureAll|: the fan-out harvests the pilot's live text (your edits
included) as the exemplar for the rest. The model's own first draft never
seeds the convention on its own — the pilot had to pass through your
review to be standing there when you fanned out.

When the convention lives somewhere other than a conjured site (an
exemplary block elsewhere in the codebase), pin it explicitly:
>
    :'<,'>ConjureExemplar
<
An explicit exemplar always beats an inferred one. |:ConjureExemplar|!
clears either kind; bare |:ConjureExemplar| shows what's in effect and
whether you chose it or it was inferred. The exemplar belongs to the
quickfix list it was set for (it lives in that list's |quickfix-context|).

With the quickfix-pro plugin installed (https://github.com/vim-pro/quickfix-pro.nvim)
the list gains live per-site status signs, an inline before/after diff on
<Tab>, and `dd` on a running site actually cancels its request. Without it
everything still works — the edits just land undecorated.

==============================================================================
7. REPEATING WITH .                                          *conjurer-repeat*

The intent is captured once, when the operator is invoked. |.| replays the
operator over a new target without prompting — the stored intent is reused:
>
    ~ip         prompt: "convert to a pure function"
    }           move to the next paragraph
    .           same intent conjured here, no prompt
<
Counts compose with the repeat as usual: `3.` repeats over three lines when
the original was linewise.

==============================================================================
8. REGISTERS AS INTENTS                                   *conjurer-registers*

A named register given before the operator supplies the intent, and no
prompt is shown:
>
    :let @r = "add type hints"
    "r~ip
<
Registers make intents first-class Vim objects: yank an intent from a
buffer (`"ryy`), persist favorites in |shada|, or cast inside a |macro|.
Dot-repeat after a register invocation reuses that register's intent as it
was at cast time.

The unnamed register (`""`) is ignored — a bare `~` always prompts.

9. COMMANDS                                                *conjurer-commands*

                                                                   *:Conjure*
:[range]Conjure {intent}
                        Conjure over [range] (default: current line) with
                        {intent} given inline: >
                            :'<,'>Conjure add error handling
<
:[range]Conjure         With no argument, reuse the most recent intent —
                        the way |:&&| reuses the last |:substitute|.

                                                             *:ConjureCancel*
:ConjureCancel          Cancel every in-flight or in-review conjure in the
                        current buffer: any live request is killed, any
                        landed draft is reverted, and the buffer ends up
                        exactly as it was. Run from inside a review tab, it
                        cancels just that one. See |conjurer-review|.

                                                             *:ConjureAccept*
:ConjureAccept          Stop reviewing and keep the buffer's current
                        content, close the diff. See |conjurer-review|.

                                                             *:ConjureReject*
:ConjureReject          Revert the draft back to the pre-conjure text and
                        close the diff. See |conjurer-review|.

                                                              *:ConjureRetry*
:ConjureRetry {feedback}
                        Re-conjure the reviewed region, sending {feedback}
                        and the rejected draft back to the model. With no
                        argument, prompts for feedback. See
                        |conjurer-review|.

                                                                *:ConjureAll*
:ConjureAll {intent}    Conjure {intent} over every valid entry in the
                        quickfix list, with bounded concurrency and
                        same-file serialization. Idempotent: a re-run casts
                        only pending and failed sites. With no argument,
                        reuse the last aggregate intent. See
                        |conjurer-aggregate|.

                                                               *:ConjureNext*
:ConjureNext {intent}   Conjure just the current quickfix entry, then
                        advance to the next — a careful one-at-a-time
                        pass. With no argument, reuse the last intent.
                        See |conjurer-aggregate|.

                                                         *:ConjureRejectSite*
:ConjureRejectSite      Revert the conjured site under the cursor (in the
                        quickfix window) or the current entry's site back
                        to its original text. Cancels the request instead
                        if the site is still running. See
                        |conjurer-aggregate|.

                                                          *:ConjureRetrySite*
:ConjureRetrySite {feedback}
                        Re-conjure the site under the cursor: the model
                        sees its applied draft (as it currently reads,
                        hand-edits included) and {feedback}, and revises
                        rather than starting over. The site shows its
                        original text while the retry is in flight. With
                        no argument, prompts for feedback. See
                        |conjurer-aggregate|.

                                                          *:ConjureRejectAll*
:ConjureRejectAll       Unwind the whole batch: drop queued sites, kill
                        in-flight requests, revert applied sites to their
                        exact original text. See |conjurer-aggregate|.

                                                           *:ConjureExemplar*
:{range}ConjureExemplar
                        Pin the range's lines as this quickfix list's
                        exemplar — a finished example every site's cast
                        must match in style and conventions. Beats any
                        inferred exemplar. See |conjurer-exemplar|.

:ConjureExemplar!       Clear the exemplar (explicit or inferred).

:ConjureExemplar        Show the exemplar in effect and whether it was
                        pinned or inferred from the pilot site.

10. CONFIGURATION                                     *conjurer-configuration*

setup({opts})                                               *conjurer.setup()*

Defaults: >lua

    require("conjurer").setup({
      -- "auto" prefers a known local CLI (claude, then codex, then gemini)
      -- and falls back to whichever direct API has a key set (anthropic,
      -- then openai, then gemini). Also: "cli", "anthropic", "openai",
      -- "gemini", any module under lua/conjurer/providers/, or a
      -- function(request, callback).
      provider = "auto",

      -- Nil uses whichever provider resolves its own default model.
      model = nil,

      -- Force a known CLI recipe by name ("claude"|"codex"|"gemini") for
      -- the "cli" provider, without hand-writing cli_cmd.
      cli = nil,

      -- Command for the "cli" provider. nil resolves a known CLI (see
      -- lua/conjurer/providers/known.lua) or the one named by `cli` above,
      -- e.g. the Claude Code CLI in streaming print mode:
      --   claude -p --model <model> --output-format stream-json
      --     --include-partial-messages --verbose
      -- A custom command owns its own flags; conjurer pipes the prompt to
      -- stdin and reads stdout.
      cli_cmd = nil,

      -- Environment variable holding the API key ("anthropic" provider
      -- only — "openai"/"gemini" use their own standard
      -- OPENAI_API_KEY/GEMINI_API_KEY).
      api_key_env = "ANTHROPIC_API_KEY",

      -- Max output tokens ("anthropic" provider).
      max_tokens = 16000,
    -- How long one request may run before it is killed. Five minutes suits
    -- a region rewrite; a caller that sends a whole worklist can need more,
    -- and a timeout says so by name rather than as "exit 124".
    timeout_ms = 300000,

      -- Adaptive thinking: better transforms, more latency ("anthropic").
      thinking = true,

      -- Lines of surrounding buffer context sent with each request.
      context_lines = 40,

      -- Aggregate conjuring (|:ConjureAll|): sites cast at once. Same-file
      -- sites always serialize regardless. See |conjurer-aggregate|.
      max_concurrent = 4,

      -- Expand bare quickfix entries to the smallest multi-line syntax
      -- node starting on their line. false = always whole-line.
      region_expand = true,

      -- Stream the model's narration into the pending region.
      narration = true,

      -- Flash the conjured text when it lands (like the |on_yank|
      -- highlight). Milliseconds; false or 0 disables.
      flash_ms = 150,
      flash_hl = "IncSearch",

      -- Set either to false to skip that mapping.
      keymaps = {
        operator = "~",   -- normal: ~{motion}, visual: ~
        line = "~~",      -- current line
      },

      -- Replace the built-in system prompt entirely (string), or nil.
      system_prompt = nil,

      -- Review the result in a native diff (against the real, live buffer)
      -- instead of just auto-applying. See |conjurer-review|.
      review = false,
    })
<

11. PROVIDERS                                             *conjurer-providers*

                                                      *conjurer-provider-auto*
"auto" (the default) resolves at cast time by trying, in order: the
`claude`, `codex`, then `gemini` CLIs (first one found on PATH wins, via
the "cli" provider) — and if none are installed, whichever of
`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` is actually set
(same order), defaulting to "anthropic" if none are.

                                                       *conjurer-provider-cli*
"cli" runs a local command. With no `cli_cmd`, it resolves one of a few
known CLIs the same way "auto" does (claude, then codex, then gemini) —
or force a specific one by name with `cli`: >lua

    require("conjurer").setup({
      provider = "cli",
      cli = "codex",   -- or "claude" / "gemini"
    })
<
The default (claude) rides your existing Claude Code auth (no API key
needed); because it is Claude Code, it may read project context (e.g.
CLAUDE.md) and has a cold-start cost of a few seconds per cast. `codex` and
`gemini` run OpenAI's and Google's CLIs non-interactively and print only
the final result (no live narration from those two — see below).

The cold start is per cast by design: every cast is an independent,
stateless request (session reuse would leak one cast's conversation into
the next). For a single `~ip` it's a shrug; for a 30-site |:ConjureAll| it
adds up — `max_concurrent` overlaps the startup latency, and the direct
API providers ("anthropic"/"openai"/"gemini") have no cold start at all,
which makes them the better familiar for large aggregate batches.

Any command works via `cli_cmd`, which owns all of its own flags and takes
priority over `cli`: >lua

    require("conjurer").setup({
      provider = "cli",
      cli_cmd = { "ollama", "run", "qwen2.5-coder" },
    })
<
A custom command's stdout is treated as a stream of the narration protocol
where the CLI speaks it; otherwise the whole output is the replacement —
this is also why `codex`/`gemini` still work with no special handling,
despite not speaking the protocol themselves. Other local runners
(opencode, aider, lm-studio, ...) work the same way — point `cli_cmd` at
however you invoke them non-interactively.

                                           *conjurer-provider-anthropic* *conjurer-provider-openai* *conjurer-provider-gemini*
"anthropic", "openai", and "gemini" each call that vendor's API directly via
curl with SSE streaming, and default to a sensible current model for that
vendor when `model` is nil. "anthropic" reads its key from the environment
variable named by `api_key_env` (default `ANTHROPIC_API_KEY`); "openai" and
"gemini" always read `OPENAI_API_KEY`/`GEMINI_API_KEY`.

                                                  *conjurer-provider-function*
A function receives the request and a callback, so any backend works: >lua

    require("conjurer").setup({
      provider = function(request, callback)
        -- request: {
        --   config, intent, filetype, text,
        --   context_before, context_after,
        --   on_narrate,   -- optional fun(line): stream narration lines
        -- }
        -- Call callback exactly once, on the main loop:
        callback(nil, transformed_text)   -- or callback("error message")
        -- Optionally return a handle to support :ConjureCancel:
        return { cancel = function() --[[ abort the request ]] end }
      end,
    })
<
                                                   *conjurer-provider-protocol*
The built-in providers instruct the model to respond as: >

    one to three short narration lines
    <<<RESULT
    the replacement text
    RESULT
<
Narration lines stream to `on_narrate`; the RESULT block becomes the
replacement. If the markers never appear, the entire output is used as the
replacement — so protocol-unaware models still work, just without useful
narration.

12. VIM IDIOMS                                               *conjurer-idioms*

Conjurer aims to behave like a native operator in every detail:

- Counts scale the motion: `2~j`, `3~~` — like `2dj`, `3dd`.
- |.| repeats the last conjure, intent included. See |conjurer-repeat|.
- Registers hold intents: `"r~ip`. See |conjurer-registers|.
- |'[| and |']| are set around the conjured text when the async replacement
  lands, so `` `[ ``, `` `] `` and chained operators over the result work.
- The result flashes briefly on arrival — the |on_yank| idiom as an async
  completion signal.
- |:Conjure| with no argument reuses the last intent, like |:&&|.
- The prompt keeps |input()| history: <Up> recalls previous intents.
- Forced motion types work: `~Vip` (|o_V|), `~vj` (|o_v|).
- 'nomodifiable' and 'readonly' buffers are refused before any request.
- One conjure is one undo step.

One deliberate deviation: native operators move the cursor to the start of
the changed text. Conjurer's change lands asynchronously — possibly while
you are typing elsewhere — so the cursor is never moved. Jump to the result
yourself with `` `[ ``.

14. PRIVACY                                                 *conjurer-privacy*

Every cast sends the targeted snippet, the surrounding context
(`context_lines` lines each side), the filetype, and your intent to the
configured provider — a local process for "cli", Anthropic's API for
"anthropic", or wherever your custom provider points. Do not conjure over
buffers whose content must not leave your machine unless your provider is
one you control.

15. HEALTH                                                   *conjurer-health*

Run |:checkhealth| conjurer to verify the environment: Neovim version,
which provider "auto" resolves to, presence of the CLI executable and curl,
and whether the API key variable is set.
